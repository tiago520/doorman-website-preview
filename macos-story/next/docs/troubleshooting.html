Choose the symptom first.

Have the original client settings, workspace, client/version, test time and exact error ready. Work from the client toward the gateway and provider; change one layer at a time, then repeat the same small request.

The request is not in Doorman.

  1. Confirm the workspace and time range.
  2. Check the endpoint the client actually uses, not just a saved example.
  3. Confirm the governed key belongs to the intended environment.
  4. Restart the client if configuration is read at launch.
  5. Check whether that client supports the selected connection method.

Visibility-only tools and directly connected traffic may not produce a governed request record.

Read the access or policy refusal.

ResponseCheck first
401Expired/revoked credential, wrong environment or a client that did not send the intended key.
403Role, entitlement or an explicit policy refusal; read the reason before retrying.
404Correct endpoint and same-organization resource; do not infer another tenant’s data.
429Budget dimension or rate-limit reason; respect Retry-After where provided.
Unavailable/upstream errorGateway/provider status, upstream credentials and the request identifier.

Check your organization role and the control’s access requirements. A restricted or unavailable signal does not mean the system found no issues. A 403 commonly indicates access is restricted; a service-unavailable response is a different problem. Read the error and any policy outcome before retrying. Ask an administrator about role or entitlement restrictions; use retry after a transient source recovers.

The Mac helper does not answer.

Open Doorman in the menu bar and choose Check this Mac. Read the named check and its suggested next step. If the helper cannot answer, have your IT contact confirm its installation for your login user using the supplied build instructions. Diagnostics do not change connection settings.

For command-line support, first follow the optional native CLI installation. CLI means command-line interface; installing the preview does not by itself guarantee that the doorman command is available in your shell. These commands belong to the native app, not the gateway repository’s separate command:

doorman status
doorman doctor
doorman status --json

The native preview supports sign-in, tool detection and diagnostics. A report can contain “Not yet” even when no check needs attention; automatic configuration and routing remain in development. Use Fix only when recommended, then run the checks again.

Restore the previous client path.

For a directly configured client, restore its previous base URL and original provider credential, then restart it and make a small test request. Use the original values you saved before setup.

For a managed device, follow the administrator’s policy rather than manually bypassing network controls.

Ask with useful context.

Include the client/version, setup method, workspace, timestamp and timezone, request ID if one exists, visible error and steps already tried. Say whether the provider responded and whether a matching Doorman record exists. Remove API keys, tokens, prompt content and private URLs from screenshots or logs before sending them.
