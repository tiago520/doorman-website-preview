Check one layer at a time, and keep the original client settings available.

The request is not in Doorman.

  1. Confirm the workspace and time range.
  2. Check the endpoint the client actually uses, not just a saved example.
  3. Confirm the governed key belongs to the intended environment.
  4. Restart the client if configuration is read at launch.
  5. Check whether that client supports the selected connection method.

Visibility-only tools and directly connected traffic may not produce a governed request record.

A control is unavailable or restricted.

Check your organization role and the control’s access requirements. A restricted or unavailable signal does not mean the system found no issues. Use the explicit error state and retry after the underlying connection recovers.

The Mac helper does not answer.

On a supported evaluation build, use doorman status and doorman doctor. Doctor reports checks without changing the machine. Follow the helper’s suggested recovery rather than repeatedly changing proxy settings.

doorman status
doorman doctor
doorman status --json

The current native repository is an evaluation build. A stub-backed preview demonstrates the UI but is not evidence of live traffic protection.

Restore the previous client path.

For a directly configured client, restore its previous base URL and original provider credential, then restart it and make a small test request. Use the original values you saved before setup.

For a managed device, follow the administrator’s policy rather than manually bypassing network controls.

Ask with useful context.

Share the client name, setup method, approximate time, visible error and the steps already tried. Remove API keys, tokens, prompt content and private URLs from screenshots or logs before sending them.
