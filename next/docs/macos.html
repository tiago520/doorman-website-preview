Native app evaluation

The current Doorman for macOS repository contains the Go helper command and Swift menu bar app. A signed customer installer is not published yet. Request the current evaluation path before installing.

The Electron app is the previous implementation. This guide follows the native Go + Swift project introduced September 1, 2026.

Request macOS access ↗

Before a source-build evaluation.

  • A Mac running macOS 14 or later.
  • Access to the current native-app source and evaluation instructions.
  • Xcode command line tools and Go for a source build; Node.js to run the development helper stub.
  • An understanding of whether the supplied helper is live or the development stub.

An ad-hoc development build is not the same as a signed and notarized public installer. Do not treat a stub’s sample “Protected” state as proof that traffic is governed.

For an authorized development build.

From the native repository, its documented build compiles the Swift interface and Go command into build/Doorman.app. The development helper supplies sample states for UI evaluation.

node stub/helper-stub.mjs
# In a separate terminal, from the same repository:
./scripts/build-app.sh
open build/Doorman.app

Use the build’s accompanying instructions for its helper and setup mode. The current repository describes routing, sign-in and helper-daemon extraction as work in progress.

Inspect status and diagnosis.

If the CLI is installed, its four everyday verbs are status, doctor, pause and resume. Doctor reports its checks without changing settings.

doorman status
doorman doctor
doorman pause 30m
doorman resume

Read the helper’s message when it is unavailable. For a live supported build, finish by verifying a real request in your own console.

Connect an API client while you evaluate.

You can use the compatible-client path without waiting for a native installer. Start with your workspace address and governed key, then inspect the first request.
