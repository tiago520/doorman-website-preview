Quick start

Connect one client first.

  1. 01

    Get a governed key

    Your Doorman administrator issues the key. Store it locally using the credential workflow approved by your organization.

  2. 02

    Set the endpoint

    Use the origin of your gateway and the provider-compatible path. The setup assistant prepares the appropriate environment variables.

  3. 03

    Make a small request

    Send one non-sensitive request from the client and inspect its record in the real console.

# Claude Code: use your administrator’s gateway origin
export ANTHROPIC_BASE_URL="https://gateway.example.com/anthropic"
export ANTHROPIC_API_KEY="YOUR_DOORMAN_KEY"

Verification

Know that it worked.

  1. 01

    Confirm the destination

    Check that the client is using the gateway origin you intended.

  2. 02

    Find the request

    Open the Control Room or request log in your real environment. Confirm the tool, identity, and observed route.

  3. 03

    Read the outcome

Troubleshooting

Keep a way back.

The request does not appear in the console.

Check the client’s supported endpoint setting, the gateway origin, and the selected environment. A client that ignores custom endpoints will not become governed merely because a variable is set.

Can I put an API key into the setup assistant?

No. The assistant deliberately has no key field. Replace its local placeholder on your machine using your approved secret-management workflow.

How do I stop routing changes?

Use the authenticated console’s observe or routing controls. To disconnect a directly configured client, restore its previous endpoint and provider credential locally.

Does every desktop app support endpoint configuration?

No. Coverage depends on the client and delivery mode. Certificate-pinned applications may remain visibility-only.
