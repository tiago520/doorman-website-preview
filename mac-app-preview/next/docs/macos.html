Native app preview

A signed customer installer and production MDM package are not published yet. Request the supported evaluation build and its installation instructions. The approved screenshots use example data.

Request Mac preview access ↗

The native app requires macOS 14 or later. Your organization may also require a particular build, workspace and endpoint policy.

Install on your Mac.

  1. Get Doorman. Use the preview build supplied by Doorman, your IT team’s installer, or your company’s self-service catalog.
  2. Follow the supplied installation steps. A development app archive and a managed installer have different helper setup requirements. Use the instructions for your exact build.
  3. Open the app and sign in. Continue in the browser, review the account, and confirm the workspace you intend to use.
  4. Follow the connection checks. The app presents the supported setup steps and any required permissions. A signed-in account alone does not mean routing is active.
  5. Check your tools. Open View apps. Read Governed, Observed and Setup available separately, then verify a supported request in your workspace.

The aim is one guided starting point: keep using your familiar tools while Doorman keeps status, coverage and diagnostics nearby. Available automatic setup depends on your build and each tool’s supported connection.

Plan an MDM or self-service rollout.

The same native app is the user-facing entry point for a managed rollout. Plan its delivery through your MDM, company app catalog or an IT-supplied package with the endpoint owner.

DecidePrepare with IT
Package and distributionConfirm the supported package, Developer ID signature, notarization and delivery method before assignment. A production package is not published yet.
Workspace and identityAgree the gateway address, intended organization and account or enrollment flow. Do not put provider secrets in a public configuration profile.
Permissions and compatibilityReview the build’s actual background-service and network requirements against your endpoint policy, VPN and existing security software.
Pilot and verificationStart with a representative device group. Check local sign-in, supported-tool coverage and a recorded request before expanding.
Updates and removalName the owner for version assignment, updates, recovery and uninstall. Use the package’s supplied removal path.

macOS device management can distribute packages through supported Apple management commands. The exact Doorman payloads and permissions must come from the released package documentation; this checklist is not a ready-to-deploy profile. Apple’s package distribution guide ↗

Keep the connection understandable.

The menu bar shows the helper’s current state. View apps explains coverage for each tool. Check this Mac runs read-only diagnostics and reports what needs attention.

  • Signed in: the Mac is linked; routing may still need setup.
  • Governed: the helper reports a supported governed connection for that tool.
  • Observed or opaque: visibility is available, but content may remain encrypted and outside governance.
  • Needs attention: read the failed check and its next step before changing settings.

On a supported live build, finish with a verified request in the intended workspace. A fixture screenshot or a successful installation is not that verification.

Evaluate the native source build.

For authorized developers, the current Go control-loop branch supports browser sign-in, account confirmation and diagnostics. Routing, automatic tool configuration and reporting are still being implemented. The native UI preserves that distinction.

Use Xcode command line tools and Go on macOS 14+. The repository’s build creates an ad-hoc signed build/Doorman.app. Follow the branch’s helper instructions; for the current development setup:

./scripts/build-app.sh
./scripts/install-helper.sh "$PWD/build/Doorman.app"
open build/Doorman.app

This registers the development helper as a per-user LaunchAgent. It is separate from a signed, notarized customer installer. Do not run the bundled fixture helper alongside the real daemon: the fixture exists only to exercise example UI states.

If the optional command is installed, doorman status and doorman doctor show the same helper state and diagnostic checks. Use the repository’s documented installation and removal instructions for that command.

Connect another way when it fits.

For an API service or a client with a configurable endpoint, use the direct connection path. Existing corporate gateways and customer-operated environments have their own deployment requirements.
