Before you connect

Know what the control covers.

Does this control every action on a machine?

No. Coverage is limited to supported actions visible through Doorman. An agent’s direct internet traffic is not automatically governed.

Are streamed tool calls enforced?

The current tool-authorization and autonomy controls enforce supported non-streaming paths. Streaming remains in shadow, recording decisions rather than promising pre-execution prevention.

Should I enable blocking immediately?

Start by reviewing shadow findings and testing representative actions. Move to enforcement once the observed policy behavior matches the intended workflow.

What about managed agents and payment actions?

Provider-managed agents expose call boundaries, not every internal step; returned usage can be recorded without promising a mid-run stop. The opt-in payment-policy API evaluates declared payment intents and approval decisions. It does not hold funds or intercept every external payment.

How do MCP and agent identity fit?

MCP governance applies to calls through the registered proxy and configured tool path. A declared agent label helps attribution but is not cryptographic authentication. Establish credentials, the visible boundary and permissions together; use the agent-governance guide for the sequence.

Give one agent a clear remit.

Bring its tools, destinations and approval requirements. Test allowed work and a held action before expanding its authority.
