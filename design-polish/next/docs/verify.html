Keep the test easy to identify.

You need access to the same organization that issued your client key, a supported configured client and a small non-sensitive request. Note its timestamp and timezone, client/version, allowed model and expected owner. Keep any response request ID so you can distinguish this test from another person’s traffic.

Find the request you just sent.

Open your real workspace’s Activity or Requests view. Search the recent records for the time, tool, and model used in your test.

The public demo is a sample organization. It cannot verify a request from your own account.

Read four things before continuing.

Open the matching record in your own authenticated console. Compare it with the client and test you just used.

  1. Identity and tool. Confirm the record belongs to the intended client and user. Unknown attribution should stay visible as unknown.
  2. Requested and selected model. A different model indicates substitution; the same model can be a valid policy outcome.
  3. Route and outcome. Distinguish observation, routing and passthrough. Review a policy event if one was produced.
  4. Recorded cost. Check that pricing evidence exists. Missing prices are not proof of a free request.

What success looks like.

One recognizable record in the right workspace.

The intended tool’s request appears with the expected identity, model path and outcome. You can explain why the gateway changed—or preserved—the route.

Then repeat with a representative task before enabling broader controls. A successful connection proves that request reached the gateway; it does not prove every application, secret detector or agent action is covered.

Decide whether to proceed.

What you seeWhat to do
Matching record, expected identity and outcomeContinue to a representative task. Keep the result as your baseline.
Response received, but no matching recordCheck workspace, time range and the effective client endpoint before calling the setup complete.
Access error, missing price or unknown identityResolve the missing evidence first; do not interpret it as zero cost or successful governance.

If the record is missing.

Check the workspace, time range, actual client endpoint and key. Restart the client if it reads configuration only at launch. An application that ignores a base-URL variable will not become governed merely because the variable is present.
